## The Identified Gap
In `exercises/practice/yacht/.meta/example.sh`, `full_house()` checks:
```bash
for die in ${!grp[@]}; do
    case ${grp[die]} in
        2|3) sum $@ ;;
        *) echo 0 ;;
    esac
    return
done
```
`${!grp[@]}` iterates in ascending numerical order of the die values. In the only canonical test for four-of-a-kind not being a full house (`1 4 4 4 4`), the single die is `1` (smaller than `4`), so `grp[1]` (count 1) is checked first.
If a mutant permits a count of 4 (such as `2|3|4)` or `[^1])`), it will still output 0 for `1 4 4 4 4` because `1` is checked first.
However, if given a four-of-a-kind where the four matching dice have a *smaller* value than the single die (e.g., `3 3 3 3 5` or `4 4 4 4 5`), `grp[3]` (count 4) is checked first. The mutants incorrectly treat this roll as a Full House and score its sum (`17` instead of `0`).

## Solution & Added Test
Appended a track-only `@test` block to `exercises/practice/yacht/.meta/template.j2`:
```bats
@test "Four of a kind is not a full house (four small, one big)" {
    [[ $BATS_RUN_SKIPPED == "true" ]] || skip
    run bash {{ solution }} "full house" 3 3 3 3 5
    assert_success
    assert_output "0"
}
```
Regenerated `exercises/practice/yacht/yacht.bats` via `bin/generate_tests --no-pull yacht` (30 tests total).
